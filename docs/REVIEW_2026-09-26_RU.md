# Проверка и доработка AgentOS 2.0.1

26 сентября 2026. Выбранный сценарий: команда агентов для работы над проектами.

## Вывод

В переданной папке уже была версия 2.0.0 с проектами, планами, чатами и согласованиями. Основные проблемы этого прохода — ошибки при прерывании работы, запоздалых ответах и запуске на Windows. Они исправлены; добавлены общий контекст проекта для исполнителей и выгрузка результата команды.

Изменения внесены в `agent-os`. Проверки выполнялись на временных базах с демонстрационными моделями и имитациями сетевых ответов. Пользовательские подключения и реальные API-ключи не настраивались, внешних публикаций не было. Git-репозитория в переданной папке нет, поэтому коммит и pull request не создавались.

## Изменения

| Область | Обнаружено | Результат |
| --- | --- | --- |
| Команда проекта | Исполнители и чаты не получали описание проекта | Название и описание передаются как справочный контекст; секреты и права не передаются |

| Расход | Резерв ещё не отправленного запроса мог списаться после перезапуска | Сохраняется признак отправки; неотправленный резерв освобождается |

| Интерфейс | Поздние ответы закрывали другую форму или подменяли задачу; двойные отправки | Ответ связан с исходным окном; повторная отправка блокируется, черновик сохраняется |

| MCP | Сверялся только выбранный инструмент; отказ в фазе проверки был недоступен | Проверяется весь каталог; отказ останавливает ещё не отправленный запрос |
| Секреты MCP | JSON-экранирование мешало скрыть сложный токен | Секрет скрывается в структуре результата до сериализации |
| Неопределённая отправка | Прерывание или некорректный ответ Telegram неверно отражали исход | Состояние `uncertain`, без автоматического повтора |
| Windows | Unix-блокировки мешали запуску; синхронизация read-only файла ломала restore | Общая блокировка Windows/Linux, исправленные backup/restore и инструкция Python-запуска |

Отчёт содержит текущие названия и описание проекта. Исторического снимка конфигурации на момент запуска пока нет. Тексты результатов сохраняются буквальными блоками, поэтому HTML из ответа модели не становится исполняемой разметкой.

## Проверка

- **161 серверная проверка прошла**: исходные 122 и 39 добавленных сценариев.
- **DOM-проверка прошла**, включая реальные запросы временному серверу, сохранение форм, медленные ответы, защиту от повторной отправки, версии публикаций, отчёт и согласования.
- **Браузерный сценарий пройден**: вход → проект → план трёх агентов → параллельные этапы и сборка → 3/3 завершены → итог. Просмотрены доска, форма проекта, план и результат при размере окна около 1280×720.
- **Windows subprocess-проверки прошли**: конкурирующие блокировки, online WAL backup, отказ обслуживания работающей базы, восстановление с верным/неверным ключом и сброс пароля с сохранением MASTER_KEY.
- Python/JavaScript проходят проверку синтаксиса; зависимости Python не конфликтуют.

Команды и ограничения окружения: [QA.md](QA.md). Проверка демо не подтверждает качество ответа реальных моделей, работу внешних аккаунтов или готовность VPS. Docker установлен, но его движок в этой сессии не запущен; контейнерная приёмка не выполнялась.

## Первый рабочий проект

1. Выполнить локальный запуск по [LOCAL-WINDOWS.md](../LOCAL-WINDOWS.md), сначала в деморежиме.
2. В «Проекты» задать цель, ограничения и ожидаемый результат в описании. Выбрать оркестратор.
3. Создать и назначить агентов либо разрешить оркестратору их создавать. Для постоянной команды можно разделить исполнение, проверку и сборку результата.
4. Создать задачу, проверить зависимости и инструкции в плане, запустить. Для ручного состава и порядка использовать «Ручной план».
5. Проверить итог и скачать отчёт. После локального сценария подключить собственную модель и повторить небольшую задачу.

## Следующие улучшения

1. **Доработка готового результата.** Замечания владельца, повтор выбранного этапа и зависимостей, сохранение исходного результата и расхода. Сейчас для новой редакции завершённой задачи нужна отдельная задача.
2. **Версии контекста и навыков.** Снимок инструкций, состава команды и настроек на запуск, история изменений навыков и сравнение результатов.
3. **Материалы проекта.** Файлы и артефакты с явным доступом конкретных агентов, ограничением размера и происхождением данных. Пока не реализовано.
4. **Приёмка на реальной модели.** Оценить распределение работы, полноту результата и расход на небольшом наборе типичных задач пользователя.
5. **Рост нагрузки.** Очередь и отдельные исполнители, затем роли пользователей и денежный учёт. Текущее ядро рассчитано на одного владельца и один процесс SQLite.

Известное ограничение: пауза во время согласования MCP прерывает этап; для продолжения может потребоваться явный повтор после ошибки. Автоматическое возобновление внешнего действия не добавлялось. Для бесшовной паузы нужно сохранять полный контекст инструментального диалога и отдельно проектировать подтверждение после возобновления.
