# Дополнение версии 2.0

Эта страница описывает сохранённые адаптеры публикации. Новые чаты Telegram, MCP, JEV, Twenty и путь подключения почты описаны в [SYSTEM-DESIGN_RU.md](SYSTEM-DESIGN_RU.md). Текущие требования Meta/VK к разрешениям и review в этой итерации полностью не подтверждены; проверку реальных аккаунтов нужно выполнить перед использованием. Связь MCP не заменяет одобрение публикации встроенного адаптера.

# Подключения и внешние действия

Это документация реализации в `app/integrations.py`, `app/telegram.py`, `app/publications.py` и `app/net.py`. В поставке нет чужих токенов или подключённых аккаунтов. Локальные тесты проверяют безопасность и протоколы на подставных ответах; успешная публикация в ваших аккаунтах пока не подтверждена. Для неё нужны выданные вам разрешения платформ и рабочий доступ VPS к их API.

## Что работает в этой версии

| Подключение | Реализованное действие | Что проверяет кнопка «Проверить» |
|---|---|---|
| Telegram | Управление задачами в личном чате; текстовая публикация в выбранный чат/канал | `getMe`, без отправки сообщений |
| VK | Текстовый пост на стене через `wall.post` | Чтение стены через `wall.get`, без поста |
| Instagram | Одно изображение или один Reel по публичному URL: контейнер → проверка готовности → публикация | Чтение ID и имени профиля |
| YouTube | Загрузка видео по публичному URL с OAuth refresh token | Получение свежего access token; видео не загружается |
| Webhook | POST одобренного содержимого в ваш внешний обработчик | Проверка HTTPS и публичного DNS; обработчик не вызывается |

Кнопка проверки не доказывает наличие всех прав публикации. VK и Telegram в этой версии не загружают вложения. Instagram-карусели, Stories, Direct, аналитика просмотров, ответы на комментарии, встроенная выдача OAuth-токенов и планирование отправки на конкретное время не реализованы. Новые платформы можно подключать через свой webhook.

## Порядок публикации

1. Создайте и проверьте подключение.
2. Создайте черновик публикации: задача, подключение, текст, заголовок и URL медиа при необходимости.
3. Просмотрите адресата и содержимое, затем одобрите публикацию в панели или боте.
4. Нажмите «Опубликовать». Адаптер примет только одобренную публикацию.
5. Проверьте внешний ID и результат на самой платформе. Для YouTube режим по умолчанию — `private`.

Встроенные публикации не запускаются непосредственно модельным ответом. В версии 2.0 агент может предложить назначенный ему MCP-инструмент, но каждый вызов требует отдельного согласования владельца. Shell и извлечение секретов подключений модели не предоставляются. Автозапуск задачи не одобряет публикации. В Telegram владелец может отдельно одобрить черновик и затем нажать «Опубликовать сейчас». Те же проверки выполняются общим сервисом публикаций.

`uncertain` означает, что отправка могла произойти, но подтверждение не получено: например, соединение оборвалось после внешнего POST. Такая операция автоматически не повторяется. Проверьте аккаунт/обработчик, прежде чем создавать новое действие. Для webhook передаётся `Idempotency-Key`; обработчик должен хранить и учитывать этот ключ.

## Telegram

Пошаговая настройка, получение своего user ID, голос и обновление существующей установки: **[TELEGRAM-START.md](../TELEGRAM-START.md)**.

В личном чате отправьте обычный текст или голосовую идею. Она сохраняется как задача со статусом `review`. Приёмный агент предлагает решение; владелец вносит правки, отклоняет или нажимает «Одобрить и выполнить». Оркестратор строит план и запускает агентов только после этого согласования. Результат и связанные черновики доступны в вебе и в том же диалоге.

Настройки контроллера задаются обычными полями веб-формы: разрешённые числовые ID, провайдеры приёмного агента и оркестратора, инструкции, лимиты, уведомления. Распознавание голоса включается отдельно и использует сохранённый официальный OpenAI-провайдер; аудио отправляется этому провайдеру. Секрет подключения — `bot_token`.

`chat_id` — отдельный адресат публикаций, числовой ID или `@имя` канала. Для бота, предназначенного только для публикаций, отключите «Управление через личный чат». Один токен нельзя включить у двух контроллеров одновременно. Текстовый канал Telegram теперь доступен в форме публикации.

Команды: `/start`, `/help`, `/tasks`, `/task ID`, `/result ID`, `/pause ID`, `/resume ID`, `/cancel ID`, `/new`. Первые 8 символов ID достаточны при однозначности. `/task ID` возвращает актуальные кнопки после изменения настроек, истечения срока прежних кнопок или потери уведомления. Новая идея вводится обычным сообщением; прежняя команда версии 1.0 `/task <описание>` заменена этим диалогом.

Разрешены только свежие сообщения владельца из private chat. Группы, пересылки, чужие и старые сообщения не обрабатываются. Срок обычного входящего сообщения — 5 минут, кнопки — сутки. Offset сохраняется до действия; при аварии между сохранением и обработкой действие может не состояться, но автоматически не повторяется. Уведомления сохраняют попытку перед отправкой; при неизвестной доставке используйте `/task ID`. Длинный текст передаётся полностью несколькими сообщениями, затем появляются кнопки.

Используется исходящий [getUpdates](https://core.telegram.org/bots/api#getupdates), без публичного webhook. Для постоянной работы компьютер или VPS должен быть включён. Первый запуск контроллера пропускает старую очередь; отправляйте `/start` после появления `last_poll_at` в карточке подключения. Код контроллера — `app/telegram.py`; устаревшие вспомогательные функции `integrations.py` оставлены для совместимости тестов, приложение их не использует.

## VK

Конфигурация:

```json
{"owner_id":-12345678,"api_version":"5.199"}
```

Секреты:

```json
{"access_token":"<пользовательский токен с нужными правами>"}
```

Отрицательный `owner_id` означает стену сообщества, положительный — пользователя. Адаптер отправляет `from_group=1` для сообщества. В проверенной [официальной схеме VK: wall.post](https://github.com/VKCOM/vk-api-schema/blob/master/wall/methods.json) указан пользовательский токен; здесь не обещается работа с токеном сообщества. Пользователю нужны соответствующий доступ к стене и разрешение приложения. Получайте доступ через [официальный кабинет VK для разработчиков](https://dev.vk.com/), с учётом доступных вашему типу приложения способов авторизации.

Проверка читает стену, а не создаёт пробный пост. Приложение ограничивает пост 15 000 символами и передаёт ID публикации в `guid`. При ответе API с ошибкой сохраняется только безопасное сообщение и числовой код; тело ответа с возможными токенами не журналируется. API-страница dev.vk.com была недоступна при подготовке; метод и поля сверены с официальной схемой VKCOM. Совместимость версии и вашего токена следует проверить в аккаунте.

## Instagram

Используется **Instagram API with Instagram Login**, хост `graph.instagram.com`. Этот вариант подключения рассчитан на профессиональный аккаунт Business или Creator и права `instagram_business_basic`, `instagram_business_content_publish`, описанные в [официальной коллекции Meta](https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api). Токены варианта Facebook Login не взаимозаменяемы с выбранным здесь вариантом.

Конфигурация:

```json
{"account_id":"<числовой ID профессионального аккаунта>","api_version":"v23.0","media_type":"IMAGE"}
```

Секреты:

```json
{"access_token":"<Instagram user access token>"}
```

`v23.0` — пример формата, а не утверждение о новейшей версии. Укажите поддерживаемую версию из вашего Meta App Dashboard. Для Reel выберите `media_type: "REELS"`. Приложение не угадывает формат по расширению URL. У изображения/видео должен быть прямой публичный HTTPS URL, доступный серверам Meta; страница просмотра облачного диска обычно не является прямым файлом.

Порядок API: `POST /{account_id}/media`, чтение `/{container_id}?fields=status_code`, затем `POST /{account_id}/media_publish` только после `FINISHED`. Приложение ждёт готовность до 180 секунд, затем сообщает об ошибке без публикации. ID созданного контейнера сохраняется для диагностики. Для Reel включено `share_to_feed=true`.

Коллекция Meta описывает [создание контейнера, готовность FINISHED и публикацию](https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api). Страницы developers.facebook.com при подготовке не открылись; прямую текущую проверку полного списка требований к медиа я не могу подтвердить. Перед первой отправкой проверьте действующие требования, разрешения и режим приложения в Meta App Dashboard. Реальная загрузка и App Review в рамках локальных тестов не выполнялись. Автоматическое продление токена Instagram не реализовано: обновляйте его в подключении до истечения срока.

## YouTube

В Google Cloud создайте OAuth-клиент и включите YouTube Data API v3. Пройдите [официальный OAuth-процесс Google](https://developers.google.com/identity/protocols/oauth2/web-server) с разрешением `https://www.googleapis.com/auth/youtube.upload` и offline access для получения refresh token. Встроенной страницы OAuth callback в этой версии нет; выданный вам refresh token добавляется вручную. Пароль Google не нужен.

Конфигурация:

```json
{"client_id":"<OAuth client id>","privacy_status":"private","category_id":"22"}
```

Секреты:

```json
{"client_secret":"<OAuth client secret>","refresh_token":"<OAuth refresh token>"}
```

`privacy_status`: `private`, `unlisted` или `public`. По умолчанию `private`; `category_id` по умолчанию `22`. В публикации нужны заголовок и прямой публичный HTTPS URL видео с ответом `Content-Type: video/*`.

Токен обновляется сервером через `oauth2.googleapis.com/token`. Загрузка использует [официальный resumable-протокол YouTube](https://developers.google.com/youtube/v3/guides/using_resumable_upload_protocol): создать сессию, получить URL из `Location`, отправить видео потоком `PUT`, сохранить подтверждённый ID. В этой версии поток отправляется одним запросом; автоматического восстановления незавершённой загрузки нет.

Лимиты **этой реализации**, не тариф платформы: файл до `200 × 1024 × 1024` байт (200 MiB), скачивание до 120 секунд, отправка до 180 секунд; заголовок до 100 символов, описание до 5 000 UTF-8 байт. Файл хранится во временном дескрипторе и удаляется после операции.

По [документации videos.insert](https://developers.google.com/youtube/v3/docs/videos/insert), загрузки непроверенных API-проектов, созданных после 28 июля 2020 года, ограничены приватным доступом до прохождения аудита. Настройки и квоты вашего Google-проекта влияют на доступность операции. Проверьте в YouTube Studio аудиторию и прочие параметры после загрузки; приложение не устанавливает декларацию made-for-kids.

## Webhook

Используйте свой обработчик, например отдельный сервис автоматизации. Приложение не предоставляет готовое подключение к произвольной социальной платформе только по её названию.

Конфигурация:

```json
{"url":"https://automation.example.com/approved-content"}
```

Секреты:

```json
{"bearer_token":"<случайный секрет вашего обработчика>"}
```

После одобрения и отправки выполняется POST:

```json
{
  "event":"publication.approved",
  "publication_id":"<id>",
  "task_id":"<id или null>",
  "text":"<одобренный текст>",
  "title":"<заголовок или null>",
  "media_url":"<URL или null>"
}
```

Заголовки: `Authorization: Bearer <секрет>` и `Idempotency-Key: <publication_id>`. Обработчик должен проверять секрет, предотвращать повтор по ключу и возвращать JSON `{"ok":true,"id":"<ID результата>"}` только после подтверждённого выполнения. HTTP 200 без нужного подтверждения не считается доказанным успехом и приводит к `uncertain`. Содержимое конфигурации ИИ-провайдеров и их ключи в webhook не передаются.

## Сетевые ограничения реализации

Все адаптеры используют общую HTTPS-библиотеку: публичные IP, порт 443, без credentials в URL, без редиректов и прокси из окружения. Все DNS-ответы проверяются, затем TCP-соединение закрепляется на проверенном IP с сохранением исходного TLS-имени и `Host`. Локальные, link-local, loopback, служебные адреса и некоторые переходные IPv6-диапазоны блокируются. Это ограничение действует и для произвольного OpenAI-compatible API.

Ответ API ограничен 2 000 000 байт; загрузка видео имеет отдельный лимит. Запрашивается несжатый ответ; неожиданное сжатие отклоняется до распаковки. Сырые ошибки upstream не выводятся. Для HTTPS-хостов с частными DNS-адресами и для локальных моделей потребуется отдельное обдуманное расширение политики, а не отключение проверок.

Проверки не заменяют настройки сервера: секреты и резервные копии следует хранить вне публичных каталогов. Набор тестов `tests/test_integrations.py` воспроизводит проверяемые сценарии без внешних токенов и без реальных публикаций.
