# Границы безопасности 2.0

Дата проверки исходников: 25 сентября 2026. Это описание реализованных мер и оставшихся ограничений, не независимый аудит и не подтверждение безопасности рабочего VPS.

## Вход и данные

Веб-панель рассчитана на одного владельца. Пароль хешируется Argon2id, доступна TOTP. Приватные API проходят проверку сессии; изменения требуют CSRF-токен и точный Origin. Проверяется Host, сессионная cookie HttpOnly и SameSite, для VPS включён Secure. В локальном HTTP-режиме Secure выключен намеренно. Ответы внешних систем выводятся текстом, CSP не разрешает произвольные внешние скрипты.

API-ключи и токены шифруются Fernet с MASTER_KEY. Тексты, результаты, аргументы инструментов и копии SQLite целиком не шифруются. Администратор с доступом к MASTER_KEY и базе может прочитать секреты. Ключ необходимо хранить отдельно от резервной копии базы; его нельзя создавать заново при обновлении.

## Полномочия агента

Навык и маска добавляют инструкции, а не права. Только явно назначенные пары MCP-сервер/инструмент доступны агенту. Новые автоматически созданные агенты не получают MCP-права. Запрос привязан к агенту, точным аргументам, родительской задаче/чату и конфигурации сервера. Схема аргументов проверяется сервером приложения, каталог повторно загружается перед исполнением.

Владелец отдельно подтверждает каждый вызов. Telegram дополнительно требует актуального предпросмотра `/tool ID`; другой бот или пользователь не может подтвердить запрос. Двойное одобрение не вызывает инструмент дважды. Изменение прав, параметров подключения или каталога требует нового запроса. `uncertain` после отправки не повторяется автоматически: нужно сверить результат во внешнем сервисе.

Эти меры не делают чужой MCP безопасным: он может скрывать опасное поведение за безобидным описанием. Его оператору доверяют, токену выдают минимальные права. Модель и внешний текст могут убеждать владельца согласовать нежелательное действие. JEV лишь советует и не отменяет проверки.

## Сеть и изоляция

Исходящие вызовы используют общий транспорт: публичный HTTPS, проверка всех DNS-адресов, закрепление проверенного IP с TLS-проверкой имени, запрет перенаправлений и прокси из окружения, ограничения времени и размера ответа. Произвольные локальные HTTP/private endpoints не разрешены. Это относится и к CRM/MCP: сервисы на том же VPS подключаются через собственный публичный HTTPS-домен.

Ядро работает без root, с read-only контейнером и отдельным volume данных. Docker socket отсутствует. Отдельный maintenance MCP получает исходники только для чтения и отдельный каталог предложений. Запрещены выход за корень, скрытые файлы и симлинки; нет shell, доступа к production secrets или изменения исходников. Предложение содержит SHA-256 прежнего файла и diff.

У контейнеров общего Compose есть внутренняя связность; компрометация соседнего сервиса требует отдельного рассмотрения. Twenty использует собственные аутентификацию, БД и upstream-образ. Первичный вход защищён временным Caddy Basic Auth. Уберите шлюз только после создания владельца и проверки отключения публичной регистрации. Не открывайте базу, Redis или порт приложения наружу.

## Восстановление и ограничения

Restore требует остановки процесса и исходного MASTER_KEY, проверяет целостность базы и расшифровку секретов, сохраняет прежнюю базу перед заменой. Затем отключает интеграции и расписания, сбрасывает сессии, кнопки, очереди Telegram и согласования инструментов. Резервирование данных Twenty и предложений выполняется отдельно.

Не реализованы командные роли, многопользовательская изоляция, неизменяемый внешний аудит, централизованный secrets manager, автоматическая ротация ключей, денежные лимиты и sandbox для запуска нового кода. Не выполнены пентест, нагрузочные испытания, полный аудит зависимостей и приёмка VPS. Недоверенные каталоги JSON Schema ограничены по размеру и внешним ссылкам, но не изолированы в отдельный процесс по CPU: подключайте проверенные MCP.
