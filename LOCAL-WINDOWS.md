# Локальный запуск на Windows

Домен и VPS не нужны. Основной вариант — Docker Desktop: приложение открывается в браузере на вашем ПК, Python и Node.js устанавливать не требуется. Ниже также описан запуск напрямую через Python без Docker.

## Первый запуск через Docker Desktop

1. Установите [Docker Desktop для Windows](https://docs.docker.com/desktop/setup/install/windows-install/). Используйте WSL 2 и Linux containers; если установщик попросит перезагрузить Windows, сделайте это. Затем откройте Docker Desktop и дождитесь запуска движка. Требования к Windows и виртуализации указаны на странице установки.
2. Распакуйте **весь архив**, например в `C:\AgentOS`. Внутри папки `agent-os` должны лежать `START-LOCAL.cmd`, `Dockerfile` и остальные файлы. Не запускайте из окна просмотра ZIP. Для первой установки выбирайте обычную локальную папку, без запятых в пути; сетевые папки не поддерживаются этим запускателем.
3. Дважды нажмите **START-LOCAL.cmd**. Первый запуск скачает зависимости и соберёт приложение; нужен интернет. Окно не закрывайте, пока идёт настройка.
4. Придумайте пароль от 16 символов и введите его дважды. Символы при вводе **не отображаются** — это нормально. Пароль нигде не печатается.
5. После проверки готовности откроется **http://localhost:8000**. Логин — **sergey**, пароль — тот, который вы только что задали.

Первый запуск включает **демо-провайдер**: он возвращает тестовые ответы без обращения к платным моделям. Создайте задачу, например «Подготовить контент-план на неделю для агентства», выберите демо-провайдера, нажмите «Создать и спланировать», проверьте этапы и запустите выполнение. Так можно проверить Kanban, агентов, граф, журнал и результат. Ответы демо не являются работой настоящего ИИ.

## Ежедневная работа

| Файл | Действие |
| --- | --- |
| `START-LOCAL.cmd` | Запускает приложение, ждёт готовности и открывает браузер; сохраняет прежний пароль и данные |
| `STOP-LOCAL.cmd` | Останавливает приложение с сохранением данных |
| `STATUS-LOCAL.cmd` | Показывает состояние контейнера и последние сообщения сервера для диагностики |

После успешного запуска окно можно закрыть: приложение продолжит работать в Docker Desktop. Закрытие вкладки браузера тоже не останавливает задачи. После перезагрузки ПК снова откройте Docker Desktop и запустите `START-LOCAL.cmd`. Пока ПК спит, выключен или Docker остановлен, задачи и Telegram-бот не работают.

Адрес привязан к `127.0.0.1`: приложение доступно с этого компьютера. Доступ с телефона через браузер или из интернета не настроен. Для Telegram используется исходящее соединение; домен и открытые входящие порты ему не нужны.

## Подключение настоящего ИИ

В разделе **«Модели и API»** добавьте провайдера, имя модели и свой API-ключ, затем выберите его для новой задачи. Реальные вызовы могут оплачиваться по тарифу провайдера. Ключ вводите в локальную панель, не отправляйте в переписку. Подписка на веб-чат сама по себе не заменяет API-ключ.

Демо-режим разрешает тестовый провайдер, но не блокирует реальный API, если вы его подключили и выбрали. Чтобы убрать демо после проверки: остановите приложение, в `.env.local` замените `DEMO_MODE='true'` на `DEMO_MODE='false'`, сохраните файл, запустите снова и отключите сохранённого демо-провайдера в панели. Старые демо-задачи сохранятся; новые создавайте с настоящей моделью.

Telegram с голосом и согласованиями настраивается по [TELEGRAM-START.md](TELEGRAM-START.md); остальные соцсети — по [docs/INTEGRATIONS.md](docs/INTEGRATIONS.md). Для реальной публикации требуется явное подтверждение и отправка владельцем.

## Где сохраняются данные

Настройки доступа и ключ шифрования лежат в **`.env.local`** рядом с `START-LOCAL.cmd`; задачи и зашифрованные токены — в Docker volume **`agentos_local_data`**. Повторный запуск использует их снова. Обычная остановка ничего не удаляет.

Храните `.env.local` в личной папке и сохраните защищённую резервную копию отдельно: без исходного ключа токены из базы не расшифровать. Не отправляйте этот файл и не включайте его в общие архивы. В отличие от Linux, на Windows доступ к нему определяется правами вашей папки NTFS.

В этой поставке предусмотрена одна локальная установка. Если запустить другую распакованную копию без `.env.local`, а том уже существует, запускатель остановится и предложит вернуться к исходной папке. Не генерируйте новый ключ для прежней базы. Не удаляйте Docker volume и не используйте `down --volumes`, если хотите сохранить данные.

## Запуск через Python без Docker

Понадобится Python 3.12 или 3.13. Этот вариант использует ту же веб-панель; Node.js для обычной работы не нужен. Откройте PowerShell в распакованной папке `agent-os` и выполните:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe scripts\configure.py --demo
.\.venv\Scripts\python.exe scripts\run-local.py
```

Если установлен Python 3.12, замените `-3.13` на `-3.12` в первой команде. Активация окружения не нужна. При настройке введите новый пароль дважды; затем откройте **http://localhost:8000**, логин **sergey**. Для первоначальной настройки без демо-провайдера используйте `--local` вместо `--demo`.

Настройка создаёт **`.env`**, а рабочая база и данные находятся в **`data`** рядом с кодом. Это отдельные файлы от Docker-варианта: он использует `.env.local` и Docker volume. Скрипт настройки не заменяет существующий `.env`. При следующих запусках выполняйте только последнюю команду; окно PowerShell держите открытым. Остановка — **Ctrl+C**, после неё дождитесь завершения процесса. Не запускайте второй экземпляр для той же базы: приложение и служебные команды используют общую блокировку.

На Windows доступ к `.env`, резервным копиям и каталогу данных определяется **NTFS ACL**, а не POSIX-битами `600`. Скрипты не проверяют и не настраивают ACL автоматически. Используйте личную папку, в её свойствах на вкладке **«Безопасность»** ограничьте доступ вашей учётной записью и необходимыми системными учётными записями. Защищайте всю папку: при сбросе пароля `.env` заменяется новым файлом, который наследует права папки. Сохраните исходный `.env` отдельно от резервной копии базы, не отправляйте его другим людям.

Резервная копия при работающем приложении:

```powershell
.\.venv\Scripts\python.exe scripts\backup.py --data-dir .\data
```

Для восстановления остановите приложение и укажите фактический путь к копии:

```powershell
.\.venv\Scripts\python.exe scripts\restore.py .\data\backups\ИМЯ-КОПИИ.sqlite3 --data-dir .\data --env .\.env --confirm-offline
```

Для смены забытого пароля после остановки приложения:

```powershell
.\.venv\Scripts\python.exe scripts\reset-admin.py --env-file .\.env --data-dir .\data
```

Ключ шифрования при этом сохраняется, активные веб-сессии сбрасываются. Действующая 2FA сохраняется; если утерян и доступ к ней, добавьте `--reset-2fa`, затем настройте 2FA заново после входа. Восстановление базы отключает Telegram, MCP, JEV, CRM и расписания и отзывает прежние согласования. Если меняли `APP_DATA_DIR`, укажите тот же фактический каталог в `--data-dir` служебных команд.

## Если не запускается

- **Docker не найден / движок не готов:** установите или откройте Docker Desktop; дождитесь готовности. Проверьте режим Linux containers. Если Docker просит включить WSL 2 или виртуализацию, выполните его инструкцию и перезагрузитесь.
- **Удалённый Docker context / DOCKER_HOST:** запускатель рассчитан на локальный Docker Desktop. В терминале проверьте `docker context ls` и выберите локальный контекст Docker Desktop. Не используйте подключение к VPS для этого запуска.
- **Порт 8000 занят:** остановите приложение, которое его использует, и повторите запуск. Не меняйте только порт в Compose: адрес, проверка Host и cookies должны оставаться согласованными.
- **Сборка не скачивает образ или пакеты:** проверьте интернет и настройки сети Docker Desktop; повторный запуск использует уже скачанные слои.
- **Ошибка после запуска контейнера:** откройте `STATUS-LOCAL.cmd` и пришлите скриншот ошибки. Содержимое `.env.local` не присылайте.
- **Пароль ввели неверно при первичной настройке:** повторите `START-LOCAL.cmd`. Если конфигурация ещё не была создана, ввод предложат снова. Существующий пароль запускатель не меняет.

Конфигурация `compose.local.yaml` отдельна от VPS-конфигурации `compose.yaml`; не объединяйте их. HTTP без TLS здесь применяется только к локальному адресу. Для публичного доступа потребуется HTTPS-развёртывание из [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

Прямой запуск Python и служебные операции проверены автоматическими тестами на Windows. Сборка Docker Desktop и работа `.cmd` требуют отдельной проверки на вашем ПК; прохождение Python-тестов не подтверждает работу Docker.
