# Twenty вместе с Агентной

В комплекте: upstream Compose релиза `twenty/v2.38.1`, исходная лицензия и изменённый `compose.twenty.yaml`. Источники и SHA-256 - `UPSTREAM.json`. Адаптация от 25 сентября 2026: префиксы сервисов, закрытые порты, обязательные секреты, закреплённый образ Twenty, лимиты ресурсов и Caddy. Изменённые файлы конфигурации Twenty распространяются с применимыми условиями upstream лицензии. Ядро Twenty не переписано.

Docker-стек в этой среде не запускался. Не подменяйте это утверждением о проверенном production deployment.

## Подготовка

Сначала настройте основное приложение по `docs/DEPLOYMENT.md`. DNS имени CRM должен указывать на VPS. В корне проекта:

```bash
python3 scripts/configure-extras.py --crm-domain crm.example.com --mcp-domain mcp.example.com
```

Скрипт создаёт `.env.extras` с правами 0600 и отдельными секретами. Он не перезаписывает существующий файл и не печатает ключи. Замените example-домены своими.

Создайте bcrypt-хеш отдельного пароля первоначального входа:

```bash
docker run --rm -it caddy:2-alpine caddy hash-password
```

Введите пароль в интерактивном запросе. Вставьте выданный хеш в поле `CRM_GATE_HASH` внутри `.env.extras`, сохранив одинарные кавычки. Значение по умолчанию специально не является рабочим хешем: без настройки начальный шлюз не должен быть опубликован.

## Запуск

```bash
docker compose --env-file .env --env-file .env.extras -f compose.yaml -f deployment/twenty/compose.twenty.yaml config --quiet
docker compose --env-file .env --env-file .env.extras -f compose.yaml -f deployment/twenty/compose.twenty.yaml up -d --build
```

Откройте CRM-домен, пройдите дополнительный пароль Caddy и создайте учётную запись владельца Twenty. Закройте публичную регистрацию в настройках Twenty. Проверьте результат из приватного окна. После этого удалите только блок `basic_auth` в `deployment/twenty/Caddyfile` и перезапустите Caddy тем же compose-набором. Это важно: Bearer API-key ядра не совмещается с первоначальной Basic-защитой.

Доступность и название настройки регистрации зависят от установленной версии. Если не можете подтвердить её отключение, оставьте шлюз или ограничьте доступ VPN, не открывая первоначальную регистрацию всем.

## Подключить к ядру

В Twenty создайте ключ в API & Webhooks и назначьте роль только для нужных объектов. В агентной панели откройте «CRM и система» → «Настроить»: HTTPS-домен, API-key, имя объекта и поля заголовка из документации своей рабочей области. Пример `tasks`/`title` требует проверки по вашей схеме.

«Записи CRM» показывает до 30 записей. Импорт читает полную выбранную запись и создаёт локальную задачу. Повтор импорта той же записи в тот же проект возвращает уже созданную задачу. Планирование стартует отдельно. Двусторонняя синхронизация, импорт всех страниц и единый вход не реализованы.

Gmail/Microsoft подключайте через поддержанные настройки Twenty и OAuth-приложения. Не вводите пароль почты в навыки агента. Смотрите официальные [настройки self-hosted](https://docs.twenty.com/developers/self-host/capabilities/setup).

## Резервирование

Встроенный `scripts/backup.py` сохраняет только базу агентного ядра. Дополнительно резервируйте PostgreSQL Twenty, volume `twenty-server-local-data` и оригинальные ключи из `.env.extras`. Для выгрузки базы используйте тот же набор compose-файлов:

```bash
docker compose --env-file .env --env-file .env.extras -f compose.yaml -f deployment/twenty/compose.twenty.yaml exec -T twenty-db pg_dump -U postgres twenty > twenty-backup.sql
```

Файл содержит данные CRM. Храните его с ограниченным доступом и проверяйте восстановление на отдельной установке.

Оценка для планирования ресурсов, не результат нагрузочного теста: сумма настроенных лимитов памяти базового профиля с Twenty = 1 + 0,25 + 2 + 2 + 1 + 0,5 = 6,75 ГиБ; нужен запас для ОС. Подбирайте сервер по реальному измерению своей нагрузки.
