# Агентная ОС 2.0.1

Русскоязычная агентская рабочая среда для одного владельца: проекты, агенты, навыки, чаты, Telegram-боты, MCP и согласование действий. Продолжает исходники «Агентной» 1.1. Дата обновления: 26 сентября 2026.

Версия 2.0.1 проверена для сценария команды агентов: исправлены исполнение планов, учёт прерываний, формы и согласования; добавлены общий контекст проекта для исполнителей, скачивание отчёта и локальный запуск Python на Windows. Подробности и следующие шаги: [отчёт проверки](docs/REVIEW_2026-09-26_RU.md).

**Начните с [START-HERE_RU.md](START-HERE_RU.md).** Полная проработка: [docs/SYSTEM-DESIGN_RU.md](docs/SYSTEM-DESIGN_RU.md).

## Что означает «на базе CRM»

Конкретный продукт из названия «Open CRM» не установлен. Для реализации выбран **Twenty** как CRM-модуль: комплект содержит официальный Compose закреплённого релиза `twenty/v2.38.1`, его лицензию и адаптацию развёртывания. Агентное ядро взаимодействует с Twenty по API. Это отдельное приложение и CRM в одном развёртывании, а не утверждение, что весь интерфейс переписан внутри исходников Twenty.

У CRM и агентного ядра отдельные учётные записи и базы; сквозной SSO и двусторонняя синхронизация ещё не реализованы. Агентный интерфейс написан на русском. Полнота перевода собственного интерфейса Twenty в этой сборке не проверена.

Источники: [репозиторий Twenty](https://github.com/twentyhq/twenty), [API](https://docs.twenty.com/developers/extend/api), [Docker](https://docs.twenty.com/developers/self-host/capabilities/docker-compose). Исходная лицензия и provenance: `deployment/twenty/UPSTREAM-LICENSE`, `UPSTREAM.json`. Enterprise-компоненты не объявляются бесплатными; применяются условия их правообладателя.

## Запуск

Windows: запуск через Python без Docker или через Docker Desktop описан в [LOCAL-WINDOWS.md](LOCAL-WINDOWS.md). Файл `START-LOCAL.cmd` запускает вариант с Docker Desktop. Для обоих локальных вариантов VPS не требуется.

Linux/macOS с Python 3.12:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python scripts/configure.py --demo
.venv/bin/python scripts/run-local.py
```

Откройте `http://localhost:8000`. Пароль задаётся при настройке. `--demo` явно включает имитацию модели, внешние API не вызываются. Для реальных моделей при первой настройке используйте `--local` вместо `--demo`; в существующей установке отключите DEMO_MODE и добавьте собственные API-ключи.

VPS: [основное приложение](docs/DEPLOYMENT.md), [Twenty](deployment/twenty/README_RU.md), [сервис предложений кода](deployment/maintenance/README_RU.md).

## Точные ограничения

- Один владелец и один процесс SQLite; это не многопользовательская SaaS-система. Число сохранённых Telegram-ботов искусственно не ограничено, но пропускная способность ограничена сервером и API. Масштабирование на сотни активных ботов не проверено.
- Три одновременных запроса моделей в ядре. Ожидание согласования MCP занимает слот агента. Большие инсталляции требуют отдельной очереди и worker-процессов.
- Лимит выходных токенов не равен денежному бюджету. JEV, транскрипция, входные токены и внешние MCP могут иметь отдельную стоимость.
- Навыки в ОС являются текстовыми инструкциями; произвольные скрипты из файла навыка не исполняются.
- MCP stdio, OAuth и двунаправленные server-to-client запросы пока не поддержаны. Текущий транспорт принимает JSON и конечные SSE-ответы; постоянный SSE-поток с незакрытым ответом может завершиться таймаутом.
- Для действий MCP нет автоматического разрешения по оценке JEV. Каждый вызов одобряет владелец. Успех MCP подтверждает ответ сервера, но не независимую проверку результата.
- Встроенного браузерного агента, RAG, генератора фото/видео, произвольного shell, запуска тестов сгенерированного кода и автодеплоя нет. Эти возможности требуют отдельных ограниченных сервисов.
- Почта подключается через возможности Twenty либо отдельный MCP; собственные Gmail/Outlook OAuth-формы и IMAP/SMTP-клиент в агентной панели не реализованы.
- Реальные аккаунты, API-ключи, VPS, Docker-стек Twenty, TLS и нагрузка в этой среде не проверены. Сборка готова для приёмочных испытаний, не сертифицирована как защищённая промышленная система.

## Проверка разработчиком

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
npm ci --ignore-scripts
.venv/bin/python tests/run_ui.py
```

DOM-проверка запускает отдельный временный сервер с тестовой моделью. Никаких реальных публикаций. Не пакуйте `.env*` (кроме примера), базы, `.venv`, `node_modules` и пользовательские секреты.
