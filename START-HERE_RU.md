# С чего начать

1. Распакуйте проект в отдельную папку. Для первой проверки на Windows используйте `START-LOCAL.cmd`. Docker Desktop должен быть установлен и запущен. Придумайте пароль при настройке.
2. Войдите в панель. Убедитесь, что видите русский интерфейс. Если включён демо-режим, ответы явно помечены как демонстрационные.
3. Откройте «Модели и API». Для реальной работы отключите демо-режим по README и добавьте ключ выбранного провайдера. Подключение модели проверяется отдельной кнопкой.
4. Откройте «Навыки и маски». Добавьте собственные инструкции. Навык описывает метод работы, маска - стиль. Ключи API сюда не вставляйте.
5. Создайте агента: роль, инструкции, провайдер, модель, навыки и маска. Права MCP пока оставьте пустыми.
6. Создайте проект, назначьте команду и оркестратора. Разрешите автоматическое создание агентов или выключите его. В ручном режиме можно создать план через кнопку с иконкой списка в карточке проекта.
7. Создайте задачу. Выберите проект. Проверьте план и запустите его. Результаты и журнал доступны в карточке задачи.
8. Для обычного общения откройте «Чаты». Можно выбрать просто провайдера или настроенного агента. При выборе проекта агент должен быть назначен в него.
9. Для Telegram создайте бота в @BotFather, затем добавьте его в «Интеграции». Укажите токен и свой числовой user ID. Выберите режим: идеи с согласованием либо диалог с агентом. Для следующего бота создайте ещё одно подключение с другим токеном.
10. Для MCP добавьте публичный HTTPS endpoint, загрузите каталог, назначьте конкретные инструменты агенту. Каждый вызов появится в «Согласованиях». Через Telegram: `/approvals` → `/tool ID` → проверка аргументов → `/approve ID` или `/reject ID`.
11. JEV настраивается отдельно в «CRM и система». Официальный кабинет: https://console.typesafe.ai/ . Здесь нужен ваш API-ключ TypeSafe, не пароль от аккаунта. Кнопка JEV в карточке проекта получает рекомендацию агента; ничего не запускает.
12. Для VPS подготовьте домен и сервер. Основная инструкция: `docs/DEPLOYMENT.md`. Twenty: `deployment/twenty/README_RU.md`. Сервис для агента-разработчика: `deployment/maintenance/README_RU.md`.

## Обновление версии 1.1

Остановите приложение. Сделайте резервную копию базы скриптом `scripts/backup.py` и отдельно сохраните исходную конфигурацию с MASTER_KEY. Распакуйте новый код отдельно, перенесите конфигурацию и подключите прежний volume/каталог данных согласно инструкции запуска. Не запускайте два процесса над одной базой. MASTER_KEY менять нельзя: он нужен для расшифровки существующих ключей.

Старые записи читаются с пустыми списками навыков, инструментов и проектов. После обновления новые разделы будут пустыми, пока вы их не настроите. На копии проверьте старую задачу и вход, затем включайте новые подключения.

## Что нужно для боевого подключения

- Адрес VPS и способ администрирования, домен с DNS на сервер.
- API-ключ хотя бы одного провайдера моделей.
- Токены нужных Telegram-ботов и разрешённые числовые user ID.
- По необходимости: TypeSafe/JEV key, адрес и ключ Twenty, MCP endpoint и токен, токены соцсетей.

Секреты вводятся в защищённые поля панели или локальную конфигурацию. Их нет в архиве. Реальная проверка провайдера может быть платной по его тарифу.
