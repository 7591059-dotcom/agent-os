# Дополнение для версии 2.0

Старые настройки при обновлении сохраняются. Теперь у каждого бота можно выбрать проект и режим «идеи» либо «чат с агентом». `/status` показывает состояние ОС; `/newchat` начинает диалог заново. Для инструментов: `/approvals` → `/tool ID` → `/approve ID` либо `/reject ID`. Согласование относится только к запросам текущего бота и пользователя. Подробный порядок: [START-HERE_RU.md](START-HERE_RU.md).

Ниже сохранена инструкция настройки и обновления прежней версии; используйте новый архив 2.0 и не меняйте существующий MASTER_KEY.

# Агентная 1.1 — управление через Telegram и веб

## Обновление уже работающей Windows-установки

1. Нажмите **STOP-LOCAL.cmd** в вашей прежней папке проекта.
2. Распакуйте новый архив отдельно. Скопируйте **содержимое его папки `agent-os` в свою существующую папку `agent-os`** с заменой программных файлов. Не создавайте вложенную папку `agent-os/agent-os`.
3. Сохраните прежний `.env.local` рядом с `START-LOCAL.cmd`. В архиве нет этого файла: пароль и ключ шифрования не заменяются. Не удаляйте Docker volume `agentos_local_data`.
4. Запустите **START-LOCAL.cmd**. Он пересоберёт образ с обновлённым приложением. Новый пароль при правильном обновлении не запрашивается.
5. Откройте http://localhost:8000 и обновите страницу сочетанием **Ctrl + F5**.

Задачи и подключения остаются в прежней базе. Старые публикации, одобренные версией 1.0, нужно одобрить повторно: новая версия связывает подтверждение и с текстом, и с настройками адресата.

## Настройка бота

1. В Telegram откройте [официального @BotFather](https://t.me/BotFather), создайте отдельного бота командой `/newbot` и получите токен. [Документация Telegram](https://core.telegram.org/bots/features#botfather).
2. В панели **«Модели и API»** добавьте модель для текстовых задач. Для проверки процесса без расходов можно выбрать существующий демо-провайдер; его ответы — тестовые.
3. В **«Интеграции» → «Подключить канал» → Telegram** заполните поля из таблицы. Секреты вводите только в своей панели.

| Поле | Что указать |
| --- | --- |
| Название | Например, «Мой помощник» |
| Токен бота | Токен, который выдал BotFather |
| Разрешённые Telegram user ID | Свой числовой ID, не номер телефона и не `@username` |
| Управление через личный чат | Включить |
| Модель оркестратора | Провайдер, который будет строить план и распределять этапы |
| Модель первого агента | Провайдер для разбора идеи; можно оставить модель оркестратора |
| Инструкции первого агента | Ваши требования к анализу идеи и предложениям |
| Уведомления о ходе выполнения | Включить, чтобы получать предложения, результаты, ошибки и черновики |
| Принимать голосовые сообщения | Включить, если подключено распознавание речи |
| OpenAI для расшифровки | Сохранённое подключение OpenAI с вашим API-ключом |
| Модель расшифровки | Например, `gpt-4o-mini-transcribe`; доступ зависит от вашего API-аккаунта |
| ID чата | Необязательно: `@username` или числовой ID **канала публикаций**, а не ваш личный ID управления |

Пример инструкций первого агента:

> Сначала выдели цель и желаемый результат. Предложи основной вариант реализации и одну альтернативу. Перечисли этапы и роли агентов. Укажи недостающие данные и ограничения. Если задача требует исполнения программы, исследования интернета или генерации медиа, прямо обозначь, какие инструменты ещё нужно подключить. Не придумывай выполненные действия. Заверши вопросом, одобрять ли выполнение или внести правки.

4. Сохраните подключение. Нажмите **«Проверить»**: проверяется токен, сообщения не отправляются.
5. Дождитесь появления времени последней проверки очереди в карточке интеграции. Затем откройте **личный чат именно со своим ботом** и отправьте `/start`. Накопленные до первого подключения сообщения намеренно пропускаются.
6. Отправьте короткую идею текстом. После проверки включите голос и повторите с голосовым сообщением.

У бота должен быть один работающий контроллер. Если тот же токен используется в другой программе, остановите её. Старый webhook нужно отключить в прежней интеграции: приложение не удаляет его самостоятельно. Это ограничение метода [getUpdates](https://core.telegram.org/bots/api#getupdates).

## Как узнать свой ID без стороннего бота

Сделайте это **до включения контроллера**. Напишите своему новому боту `/start`, затем откройте PowerShell и выполните блок ниже. Он читает очередь вашего бота через официальный API и показывает ID и имя отправителя. Выберите строку со своим именем; ID автоматически никому доступ не выдаёт.

```powershell
$agentBotSecret = Read-Host 'Вставьте токен BotFather' -AsSecureString
$agentBotToken = [System.Net.NetworkCredential]::new('', $agentBotSecret).Password
try {
    $agentBotUpdates = Invoke-RestMethod -Method Post -Uri ('https://api.telegram.org/bot' + $agentBotToken + '/getUpdates') -Body @{timeout=0; allowed_updates='["message"]'}
    $agentBotUpdates.result | Where-Object { $_.message.chat.type -eq 'private' } | ForEach-Object {
        [PSCustomObject]@{ID=$_.message.from.id; Name=$_.message.from.first_name; Username=$_.message.from.username}
    } | Format-Table -AutoSize
} catch {
    Write-Host 'Не удалось прочитать очередь. Проверьте токен, сеть и отсутствие другого контроллера/webhook.'
} finally {
    Remove-Variable agentBotSecret,agentBotToken,agentBotUpdates -ErrorAction SilentlyContinue
}
```

Если список пуст, отправьте боту ещё одно сообщение и повторите. Токен вводится скрыто и не вставляется в строку истории команд. Метод и поля отправителя описаны в [Telegram Bot API](https://core.telegram.org/bots/api#getupdates). Этот PowerShell-блок подготовлен для Windows; в среде разработки Windows не было, поэтому его выполнение на вашем ПК ещё не подтверждено.

## Обычный рабочий процесс

**Идея → предложение → правки или одобрение → агенты → результат → черновик → одобрение содержания → публикация.**

- Напишите или надиктуйте идею. Она появится на дашборде в согласовании. После голоса бот сначала покажет распознанный текст.
- Первый агент предложит решение. Кнопка **«Внести правки»** переводит диалог в режим уточнений: следующее текстовое или голосовое сообщение относится к этой идее. `/new` отменяет ввод правок и возвращает приём новых идей.
- **«Одобрить и выполнить»** разрешает построение плана и выполнение агентами. Это может расходовать API-кредиты. Одобрение идеи не разрешает публикацию.
- Готовый результат придёт в бот. Его можно открыть в вебе вместе с журналом, агентами и этапами.
- **«Подготовить публикацию»** предлагает включённые каналы. Выберите адресата, проверьте весь текст и при необходимости измените текст, заголовок или ссылку на медиа.
- **«Одобрить содержание»** ещё ничего не отправляет в канал. Для отправки нажмите отдельную кнопку **«Опубликовать сейчас»**.

В вебе кнопка **«Новая идея»** использует тот же процесс и настройки выбранного контроллера. Telegram-уведомления такой идеи направляются первому ID из его разрешённого списка. Веб-владелец видит все задачи; каждый Telegram-диалог управляет привязанными к нему идеями. Старые обычные задачи из версии 1.0 остаются в вебе: они не привязываются к Telegram задним числом.

Для задач, созданных обычной кнопкой «Новая задача», сохраняется прежний процесс планирования через веб. Если нужны согласования и продолжение в Telegram, создавайте их через **«Новая идея»**.

## Команды

| Команда | Действие |
| --- | --- |
| `/start`, `/help` | Справка |
| `/tasks` | Последние задачи этого диалога |
| `/task первые8символовID` | Актуальное состояние, предложение и кнопки, существующие черновики |
| `/result первые8символовID` | Результат задачи |
| `/pause ID`, `/resume ID`, `/cancel ID` | Пауза, продолжение, отмена |
| `/new` | Отменить режим правок и принимать новую идею |

Для новой идеи команды не нужны — достаточно обычного сообщения. Голос, начинающийся с названия команды, не исполняется как команда.

## Голос, расходы и доступ

Приложение принимает Telegram voice в OGG, **до 300 секунд и 10 МиБ**. Это собственные ограничения приложения, а не заявление о лимитах Telegram или OpenAI. Между голосовыми установлен интервал 15 секунд. OGG поддерживается [официальным API транскрипции OpenAI](https://developers.openai.com/api/reference/resources/audio/subresources/transcriptions/methods/create).

После включения голоса аудио загружается из Telegram и передаётся в OpenAI для расшифровки. Копия аудио не записывается в базу приложения; текст идеи сохраняется. У провайдеров действуют собственные правила хранения. Распознавание оплачивается отдельно от текстового анализа и не включено в счётчик выходных токенов задачи. Проверяйте расшифровку и предложение перед одобрением.

Подписка на веб-чат не заменяет API-ключ. Для текста можно назначать поддерживаемых системой разных провайдеров; голос в этой версии подключается через официальный OpenAI API.

На локальном ПК **Docker и компьютер должны работать, нужен интернет**. Когда ПК спит или выключен, бот не обрабатывает сообщения. Управляющие сообщения старше пяти минут игнорируются; после долгого простоя отправьте идею снова. Для постоянной работы позже перенесите систему на VPS. Входящий порт и домен для самого Telegram-контроллера не нужны.

## Защита и восстановление

Управление принимается только из личного чата разрешённого пользователя. Группы, пересылки и посторонние отправители игнорируются. Кнопки действуют для конкретного бота, пользователя, сообщения и версии предложения; старые и повторные нажатия не запускают действие заново. После изменения настройки подключения запросите актуальные кнопки через `/task ID`.

При редактировании одобренной публикации одобрение сбрасывается. Если результат отправки неизвестен, она получает статус `uncertain`: автоматического повтора нет. Проверьте сам канал перед новой отправкой. Если уведомление потерялось, `/task ID` покажет состояние и новые кнопки.

При восстановлении резервной копии Telegram отключается, старые кнопки удаляются и незавершённые согласования требуют проверки. Смена пароля веб-входа сама по себе не отзывает доступ Telegram: удалите user ID или отключите контроллер в интеграциях.

Агенты этой версии выполняют текстовые задачи. Они не запускают произвольные программы, не исследуют интернет и не генерируют изображения/видео встроенными инструментами. Instagram и YouTube требуют готового медиа по публичному HTTPS URL; Telegram и VK сейчас публикуют текст. Настройка соцсетей — [docs/INTEGRATIONS.md](docs/INTEGRATIONS.md).

Код и протоколы проверены локальными автоматическими тестами с подменёнными внешними ответами. Ваш токен, реальное голосовое сообщение и публикация в вашем канале ещё не проверялись; первая приёмка выполняется после подключения аккаунтов.
